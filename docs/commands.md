# Commands

Apps and tunnels that `koppler` starts run detached, so they keep running after the terminal or agent session that started them ends.
`koppler --help` lists every command, and `koppler help <command>` or `koppler <command> --help` shows its options and an example.

## For you

| Command                                                                                                                      | What it does                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `koppler init [--new "<name>" --envs qa,prod] [--root <dir>]... [--stack <dir>] [--pick] [--no-fetch]`                       | Find your repos and the stack, or start a new stack and pick its apps                                                                                                                                                                                                                                    |
| `koppler canvas [start] [--board "<name>"] [--no-open] [--new-address] \| stop`                                              | Start the canvas if needed and open it in your browser, on a board when one is named (an open canvas switches to it); `--new-address` gives it a new address, so every one given out before stops working; `stop` stops it                                                                               |
| `koppler use [stack] [--boards]`                                                                                             | List the stacks on this machine (`*` marks the one in use), switch to one, or list its boards                                                                                                                                                                                                            |
| `koppler db [local <database> <host:port[/database]> \| local <database> --clear]`                                           | List the stack's databases, the apps that use them and where each runs on this Mac; set or forget the address a database switched to Local uses, kept on this Mac only                                                                                                                                   |
| `koppler link [<url> \| update \| discard \| pr]`                                                                            | Use a stack shared on GitHub; then bring in its changes, drop yours, or open a pull request with yours                                                                                                                                                                                                   |
| `koppler doctor [app...] [--env <env>] [--no-tunnels <app,...>]`                                                             | Can it run here: the tools your stack needs, then what you still have to do for these apps                                                                                                                                                                                                               |
| `koppler watch <app>`                                                                                                        | Restart an app when a file in its clone changes, as it was started, its wiring included; a run starts this beside each card set to Auto-restart, and Stop ends it                                                                                                                                        |
| `koppler doctor --secrets [app...]`                                                                                          | Also test that each stored secret works, for example that the database connects                                                                                                                                                                                                                          |
| `koppler doctor --flow`                                                                                                      | Test every connection of what runs now, like the canvas's Flow check                                                                                                                                                                                                                                     |
| `koppler doctor --approve`                                                                                                   | Review everything the stack would run or write (checks, start commands, code changes) and allow it; asks you, never a script                                                                                                                                                                             |
| `koppler secret set\|list\|remove\|psql <app>[@<env>] [<NAME>] [--stdin] [--pgpass]`                                         | Store and manage secrets; a value never shows. `psql` opens the database with the stored connection                                                                                                                                                                                                      |
| `koppler status [--apps] [--debug [name...]] [--json]`                                                                       | What Koppler runs; `--apps` adds the stack's apps and clones; `--debug` gives versions and scrubbed logs for a bug report. With `--json`, each app has a `status`, as its card shows it: `waiting`, `building`, `running`, `unhealthy`, `exited`, `failed-to-start` or `secret-missing`, with a `detail` |
| `koppler logs <name> [-f] [-n <lines>] [--run <id>] \| --all [-f] [--since run\|1h\|all] [--lines <n>] [--except <app,app>]` | Show or follow a log, secrets masked; `--run` shows the log a past run kept; `--all` shows every app on the board in one stream, in the order its lines came                                                                                                                                             |
| `koppler shell <app> [--env <env>] [--query]`                                                                                | A shell in the app's clone with the settings its run starts it with (where the apps it calls answer), never its secrets; `--query` opens psql on its database with the stored connection.                                                                                                                |
| `koppler reload <app> [--restart]`                                                                                           | Hot reload a Flutter app Koppler runs (Started by Koppler), or with `--restart` hot restart it; the card's Reload button does the same once the app is on the device, Shift-click restarts                                                                                                               |
| `koppler traces start\|stop\|open [<app>]`                                                                                   | Collect traces from the apps Koppler starts (Jaeger in Docker; each app is given the standard `OTEL_EXPORTER_OTLP_*` settings and its id as `OTEL_SERVICE_NAME`) and follow one request across them to where it failed; the bar's Traces button and each card's do the same                              |
| `koppler stop <name...> \| --all`                                                                                            | Stop by name, or every app and tunnel (asks first); changes stay until `koppler down`                                                                                                                                                                                                                    |
| `koppler restart <name>`                                                                                                     | Stop an app or tunnel and start it again the way it was started                                                                                                                                                                                                                                          |
| `koppler history [session \| done [<id>] [--failed "<why>"] \| pin\|unpin <id>]`                                             | Recent runs and Stops and how they ended; `session` gathers what happened since the last Stop, for a bug report; `done` marks a run finished. Each run keeps its apps' logs (History opens them); the newest 20 runs keep theirs, and `pin` keeps a run's for good                                       |
| `koppler query <app> [--env <env>] [--secret <NAME>] "<sql>"`                                                                | A read-only query with the app's stored connection; on production, in your own terminal only                                                                                                                                                                                                             |

## Used by the agent add-on

You can run these yourself too; the agent uses them to do its part.

| Command                                                                                                                                                                                      | What it does                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `koppler sync [--stack <dir>] [--rescan] [--github]`                                                                                                                                         | Reload the stack and your clones; `--github` also reads the repos not cloned here from GitHub                                                                                                                                                                                               |
| `koppler refresh [--no-sync]`                                                                                                                                                                | After changes made outside the canvas: sync, then an open canvas reads the stack and its board again, in place                                                                                                                                                                              |
| `koppler discover [app...] [--no-fetch] [--no-github]`                                                                                                                                       | What the repos say: local ports, tunnels, calls, conflicts and gaps, then what could be added to `stack.json`                                                                                                                                                                               |
| `koppler discover --deployed`                                                                                                                                                                | Also draft deployed addresses, settings, secret names, queues and calls from the infrastructure code, with the Kafka topics, event buses, pipes, rules and subscriptions that feed the queues, and the S3 buckets, API Gateways and Step Functions the apps use                             |
| `koppler discover --deployed --aws [--env <env>]`                                                                                                                                            | Also check what AWS runs, read-only with each app's AWS profile (its view role when there is one): every EventBridge Pipe and Lambda Kafka listener, as `OK` (the stack has it), `FOUND` (AWS has it, the stack does not) or `MISSING` (the stack says a pipe reads a topic, and none does) |
| `koppler discover --apply`                                                                                                                                                                   | Keep the agreed findings in the stack                                                                                                                                                                                                                                                       |
| `koppler discover --find "<name,...>"`                                                                                                                                                       | The repos behind names in a description: the stack, your clones, your GitHub orgs                                                                                                                                                                                                           |
| `koppler add <repo or folder>...` / `koppler remove <app>`                                                                                                                                   | Add apps to the stack from your clones, or take one out                                                                                                                                                                                                                                     |
| `koppler add --outside "<name>" [--called-by <app,...>] [--sends-to <app,...>] [--url <address>] [--why "<why>"]`                                                                            | Add a system that never runs here (a SaaS API, a payment provider): the apps that call it, and the apps it calls (a webhook). The canvas has the same under "Add outside system…"                                                                                                           |
| `koppler plan [app...] [--env <env>]`                                                                                                                                                        | What the newest run starts, restarts and stops; with apps, the tunnels they need                                                                                                                                                                                                            |
| `koppler plan --wire <caller> <callee> [--device ios\|android\|phone\|<id>]`                                                                                                                 | What to change so a caller uses a local app                                                                                                                                                                                                                                                 |
| `koppler up <app...> [--cable <caller>:<callee>]... [--env <env>]`                                                                                                                           | Start apps as a run, added to what already runs: recorded like Run on the canvas, so the canvas, history and Stop see it                                                                                                                                                                    |
| `koppler up --board "<name>" [--env <env>] \| --run <id>`                                                                                                                                    | Start a saved board, or a recorded run: tunnels, local queues, then apps, callees first, each waited for                                                                                                                                                                                    |
| `koppler wait <app...> --healthy\|--up\|--down [--timeout <seconds>] [--json]`                                                                                                               | Wait until apps are healthy (answering, and passing their ready check), up or down; fails on a timeout or an app that exits, naming each app's state                                                                                                                                        |
| `koppler do <app> <command> [--arg <name>=<value>]... [--env <env>] [--yes]`                                                                                                                 | Run one of an app's commands from the stack (`commands`, such as seed or migrate) in its clone with its secrets, after `koppler doctor --approve`; the same commands are buttons on the card                                                                                                |
| `koppler mcp`                                                                                                                                                                                | Serve MCP on stdio for any agent: `status`, `logs`, `doctor`, `plan`, `history`, `wait` and `say` as tools with strict inputs; add it with `claude mcp add koppler -- koppler mcp`. Starting, stopping and approving are not offered                                                        |
| `koppler agent init [--agent claude,copilot,vscode,opencode] [--dry-run]`                                                                                                                    | Link the skill into each agent on this Mac (Claude Code, GitHub Copilot CLI, VS Code, OpenCode) and register `koppler mcp` with it; a config that is not plain JSON is left alone, with what to add                                                                                         |
| `koppler down [--run <stop id>]`                                                                                                                                                             | Stop and revert: stop what Koppler runs, undo every change, put branches back                                                                                                                                                                                                               |
| `koppler run <app> [--env <env>] [--device ios\|android\|phone\|<id>] [--lan] [--no-test] [--dry-run] [--mock]`                                                                              | Start one stack app, any kind. `--no-test` skips the check that its stored secrets work; `--mock` answers its mock responses from the stack in its place                                                                                                                                    |
| `koppler run <name> [--cwd <dir>] [--port <n>] [--bind <address>] [--ready <url>] [--keep-alive] -- <command...>`                                                                            | Start any command, detached and logged; it never gets secrets. `--keep-alive` starts it again whenever it exits (for tunnels). `--bind` says which local address it listens on, when two share a port                                                                                       |
| `koppler switch <app> <branch> [--set-aside \| --take-along]`                                                                                                                                | Switch a clone to the board's branch; `--back` undoes it                                                                                                                                                                                                                                    |
| `koppler recipes [app] \| --remember <app> --why "..." [--when ...] [--any-os] [--private] \| --apply <app...> [--env <env>]`                                                                | Remembered code changes: list them, keep the last edit, apply the matching ones and say which do not match the run. A stack's own, under `apps.<id>.localChanges`, are applied only after `koppler doctor --approve`; one without `when` applies on every run                               |
| `koppler listen take \| as <id> \| stop`                                                                                                                                                     | Wait for requests from the canvas; one agent session at a time. The canvas shows the session's name in Claude Code beside Agent, with its session id and folder on hover                                                                                                                    |
| `koppler board new "<name>" [--add <app,...>] [--cable <caller>:<callee>]...`                                                                                                                | Make a board of your own, with its apps and cables; an open canvas adds it to your boards and switches to it                                                                                                                                                                                |
| `koppler board share "<name>"`                                                                                                                                                               | Propose one of your boards to the team: a pull request on the stack's repo on GitHub; a stack not on GitHub keeps it in its file to commit                                                                                                                                                  |
| `koppler board open <file or link> [--no-open]`                                                                                                                                              | Open a board from a file or a GitHub link: it joins your boards and the canvas opens on it; the board picker's Reload reads it again from there                                                                                                                                             |
| `koppler board new\|edit "<name>" [--request "<words>"] [--phase "<name>"] [--step <from>:<to>[="<note>"]]...`                                                                               | Make it a feature board: the request it came from, and the stack's links it uses as numbered steps, each in the phase named before it                                                                                                                                                       |
| `koppler board edit "<name>" [--propose-step <from>:<to>[="<why>"]]... [--unstep <from>:<to>]...`                                                                                            | Propose a step, dashed on the map until the user accepts it there, or take one off; a card is an app's id, `queue:<id>` or `database:<id>`                                                                                                                                                  |
| `koppler board delete "<name>"`                                                                                                                                                              | Move one of your boards to Recently deleted, as the board picker does; an open canvas does it too, and Recently deleted brings it back                                                                                                                                                      |
| `koppler board new\|edit "<name>" ... --arrange`                                                                                                                                             | Lay the board out afresh, as Arrange on the canvas does: at once when it is on screen, else when it is next opened                                                                                                                                                                          |
| `koppler board new\|edit "<name>" ... --propose`                                                                                                                                             | Ask the user first: the change shows in the canvas inbox, and is made only when they say yes                                                                                                                                                                                                |
| `koppler board edit "<name>" [--add <app,...>] [--remove <app,...>] [--cable <caller>:<callee>]... [--uncable <caller>:<callee>]... [--branch <app>=<branch>]... [--note <app>="<note>"]...` | Change a board, even one open on the canvas: the canvas shows the change and keeps it; cards it does not touch stay put                                                                                                                                                                     |
| `koppler stack get [<path>]` \| `set <path> <value>` \| `unset <path>`                                                                                                                       | Read or change any field of the stack, such as `apps.orders.url` or `apps.orders.envs.prod.prereqs`; each change is checked before it is kept. With the canvas's settings, the only way to change `stack.json`                                                                              |
| `koppler stack lock <path>` \| `unlock <path>` \| `locks`                                                                                                                                    | `lock` keeps a field as it is for commands, the canvas and the agent; `unlock` asks you in the terminal, so an agent cannot; `locks` lists them                                                                                                                                             |
| `koppler stack check [<file>]`                                                                                                                                                               | Every check the stack must pass, for the team repo's CI: prints each problem and exits 1. See [ci.md](ci.md)                                                                                                                                                                                |
| `koppler stack schema`                                                                                                                                                                       | The JSON Schema of `stack.json`, for an editor's `$schema`                                                                                                                                                                                                                                  |
| `koppler stack propose`                                                                                                                                                                      | A pull request on the stack's repo with what this copy changed since its last commit, made on the stack as the team has it now                                                                                                                                                              |
| `koppler actions [--json]` \| `add '<json>'` \| `add --file <json file>` \| `clear [--app <app>]`                                                                                            | The action log: every temporary change, which Stop undoes. `add` logs a change before it is made (checked, never a secret value); `clear` empties it after a revert. The only way to write it                                                                                               |
| `koppler status step <app> "<label>" done\|todo\|user\|failed [--detail "..."] [--copy "..."] [--port <n>] [--log <file>]` \| `step <app> --clear`                                           | Set one step of an app's checklist on its card, or take the agent's steps off                                                                                                                                                                                                               |
| `koppler say [--file <json>]` \| `--answered <id> [--text "..."]`                                                                                                                            | Show a question or result on the canvas, with choices to press; `--answered` closes one that was answered in the chat                                                                                                                                                                       |

## Conventions

- `koppler --version` prints the version, or the commit when Koppler runs from a clone.
- Commands that report something take `--json` for scripts and agents.
- Commands that stop everything ask first; in a script, add `--yes`.
- Exit codes: 0 done, 1 failed, 2 wrong usage.

## Environment

| Variable             | Default                  | What                                                                  |
| -------------------- | ------------------------ | --------------------------------------------------------------------- |
| `KOPPLER_STATE`      | `~/.local/state/koppler` | Run state, boards, history, the action log, logs                      |
| `KOPPLER_CONFIG_DIR` | `~/.config/koppler`      | Which stack is in use, private stacks, approvals                      |
| `KOPPLER_PORT`       | `4747`                   | The canvas's port                                                     |
| `KOPPLER_SECRETS`    | the Keychain             | A folder for secrets instead of the macOS Keychain                    |
| `KOPPLER_KEYCHAIN`   | your default keychain    | A keychain file of its own for secrets, e.g. a throwaway one in tests |
| `KOPPLER_TEMP`       | `<state>/run`            | The run state: boards, history, the action log                        |
| `KOPPLER_LOGS`       | `<state>/logs`           | The apps' logs                                                        |
